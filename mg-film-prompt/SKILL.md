# MG 动效短片：风格选择与提示词生成

为用户的需求产出**一份可直接使用的完整制作提示词**：先选对风格，再把用户的内容定制进该风格的提示词模板。
提示词的执行者是任意"能写代码并执行命令的助手"——画面、动画、配乐、音效全部由代码生成，无需生图或生视频模型。

## 方法论核心

1. **提示词 = 通用骨架 + 风格专属 5 段**。通用骨架（角色设定、工作方法、规则、工艺清单、自评、交付）所有风格共用、逐字复用；风格专属 5 段（Style / Output / Suggested technical route / Creative seed / Signature features）每种风格一份模板。逐字保留的原因：这些措辞经过原项目 15 支片、每支多轮评审迭代打磨，改写会损失已验证的质量约束。
2. **Signature features 是风格的"身份证"**：可检验的技法清单（具体到缓动曲线参数、帧数、色值、层结构），成片照它评审。定制时**绝不删改**，只重写 Creative seed。
3. **Creative seed 要有节拍感，但不是逐拍分镜**：交代钩子在哪、往哪个方向升级、峰值放在 60–75%、结尾怎么收；具体每拍做什么留给执行者。只写 1 个样板拍作为密度标尺。
4. **确定性渲染**：每一帧都是时间 t 的纯函数（种子随机、无实时时钟），逐帧渲染后合成；配乐音效与画面读同一份节拍表（cue sheet）。
5. **评审迭代**：成片后用独立评审提示词打分并出修改清单，回炉修改，至少两轮。
6. **Creative seed 是 brief，不是分镜**。它交代"为什么这么拍、必须守住什么、质感什么样"，把"每一拍具体怎么动"留给执行者。写死逐拍微指令会同时造成两个后果：执行者失去判断空间（提示词虽写着 "you may change the concept"，但每个数字都成了锁），以及散文精度承载不了代码精度——帧数、像素、曲线写进自然语言，既不可校验又互相冲突，执行者只能反复权衡。控制力要么交给 cue sheet（数据、可校验），要么交还给执行者。
7. **适用边界**：本方法为 5–30 秒的单概念短片设计（默认 10 秒）。**超过 30 秒仍想做**，改用章节模式（`references/chapter-mode.md`）：每章内仍是一支 10–20 秒短片，章间只共享画布、色板、不变量；不要线性拉长单段节拍表。多场景叙事或对白驱动的需求，拆分为多支短片分别生成，或明确告知用户此方法不适用。

## 工作流程

### Step 1 · 明确需求

从用户消息中提取以下信息；**能推断的就推断，只缺关键项才追问**（一次问清，不超过一轮）：

- 内容与目的：宣传/讲解/包装什么
- 品牌名或产品名（没有就用虚构名）
- 关键文案或口号（屏幕文字用受众语言，中文需地道、标点正确）
- 时长（默认 10 秒）与画幅（默认 1920×1080 横屏；社交竖屏 1080×1920）。**时长决定档位**：≤30s 走单段节拍；>30s 走章节模式并先读 `references/chapter-mode.md`，不要用单段节拍去拉长
- 情绪气质、参考片/参考图（若有）
- 是否已指定风格
- 执行环境：能否跑网页渲染（Node + Chrome）与 ffmpeg；是否有 Blender（决定重路线的 3D 渲染系是否可选）。环境未知时**默认按轻量路线选风格**，并在交付说明中注明环境要求

### Step 2 · 选风格

读 `styles/catalog.md`，按其决策表（内容/目的 → 情绪气质 → 画幅/平台 → 制作成本）选出风格：

- 用户点名 → 用它；用户给了参考 → 从参考判断；
- 否则给出 **1 个主推 + 最多 2 个备选**，各一句话理由，并按主推直接继续（不必等待确认，除非需求关键信息缺失）；
- 15 种都不合适 → 按 `references/new-style-template.md` 新造一个风格的专属 5 段。

### Step 3 · 生成提示词

读 `references/prompt-skeleton.md`（通用骨架）和 `styles/templates/<编号>.md`（所选风格模板），按下表拼装：

| 段落 | 来源 | 处理 |
|---|---|---|
| 开头角色段（You are the director…） | 骨架第 1 块 | **逐字保留** |
| `# Style` | 风格模板 | 逐字保留 |
| `# Output (fixed)` | 风格模板 | 画幅/时长按需求调整（只改数值，`(fixed)` 标签字样保留；规则见下） |
| `# Suggested technical route` | 风格模板 | 逐字保留 |
| `# Creative seed` | 风格模板仅作结构参照 | **按用户需求整段重写**（规范见下） |
| 导演自主权段（You are the director: you may change…） | 风格模板 | **逐字保留**，紧跟在 seed 之后 |
| `# Signature features and key techniques` | 风格模板 | **逐字保留** |
| `# How to work` 至结尾（Rules / Craft checklist / 自评 / Deliver） | 骨架第 3 块 | **逐字保留** |

完整的拼装实例见 `references/worked-example.md`——拿不准"重写到什么程度"时，先看它。

**Output 调整规则**：帧数 = 时长 × fps；竖屏把分辨率改为 1080×1920；时长 ≠ 10 秒时同步改骨架开头段的 `10-second` 字样，并按比例缩放 seed 的时间轴（保持 HOOK < 0.5s、hero moment 在 60–75% 处、结尾定格 0.8–1.2s）。

**Creative seed 重写规范**——seed 是 brief，不是分镜。用标签把"锁死什么"与"放权什么"分开，这是唯一能同时保住风格还原度与执行者判断力的写法：

```text
# Creative seed
「中文片名」English tag — 一句话风格定位（风格根性 + 用途/平台）

[LOCK] IDEA
- 论点：<一句话，全片只服务这一句；它是判断所有取舍的标准>
- 论证脊柱：<A → B → C → 结论，3–5 个环节，交代先后与因果关系>
- 不变量：<必须跨拍一致的数字/关系，≤3 条；只留承载论证的，例如"结尾概率与开场一致">

[LOCK] CHAPTERS            ← 仅时长 > 30 s 时写；≤30 s 删掉这块
- 01 0.0–19.0s「章名」章任务：<这一章要让观众明白什么> | 收尾：<Chapter 卡/过渡形态>
- 02 …（每章 10–20 s，详见 references/chapter-mode.md）
HERO: <时间点>（全片唯一，置于 60–75% 处）

[LOCK] SURFACE
- 色板：3–5 个具体 hex（不得突破该风格 Signature 的配色约束）
- 字体 / 质感：<字体气质 + 纹理与网点处理>
- 构图：<画幅适配逻辑，竖屏需写明竖向构图；大画布需写明镜头如何串场>
- Sound：<音乐风格 + BPM + 关键拟音方向>（与画面 hit 对齐）

[REGISTER] 样板拍（只写 1 个，是密度标尺，不是逐拍规范）
- 0.0–1.2s HOOK: <这一拍的质感、节奏与信息密度，作为全片其余节拍的参照>

[FREE] 其余节拍、微动效、缓动曲线、转场机制——由执行者设计，并在交付报告中说明选择理由
```

**配额**（校验脚本会查，超标即判不合格）：

| 指标 | 限额 | 超标意味着 |
|---|---|---|
| seed 占全文 | ≤ 25%（上限 35%） | brief 膨胀成完成版 treatment |
| 帧/px/百分比级微指令 | ≤ 0.8 / 拍 | 散文承载不了代码精度，且会互相冲突 |
| 完整样板拍 | 1 个 | 多给几个就变成逐拍规范 |
| [LOCK] 不变量 | ≤ 3 条 | 每条都在压缩执行者的修改空间 |

三条硬约束：

- **只锁"必须发生"与"必须相等"，不锁"第 3.5 秒手抬 6px"**。数字要么承载论证（概率、权重、总数），要么给判断标准（"错峰 2–4 帧"），不要给逐拍读数。
- **禁令写成禁令，别在别处又要求。** 写"禁渐变光晕"就别在下一句要求 token 发光；二者只能留一个。
- **不写未定义的量词。** "N 层""若干"执行者无法确定；要么给具体值，要么明说由执行者决定。
- seed 中保留该风格的"seed 基因"（见 catalog 各风格条目）；品牌名一律虚构（用户主动提供的品牌名除外）；素材只用 CC0/公有领域/OFL 等可商用许可；提示词主体沿用模板的英文骨架 + 中文风格特征双语约定，屏幕文字用受众语言。

### Step 4 · 质量自检

生成后逐项核对，不通过就改：

- [ ] 三段结构齐全，通用部分（开头段、导演自主权段、尾部段）未被改写
- [ ] Signature features 与所选模板**逐字一致**；Output 与需求一致（分辨率/帧率/时长/帧数自洽）
- [ ] 时长 ≤ 30s；若 > 30s 已按 `references/chapter-mode.md` 声明章节，每章 10–20s
- [ ] Creative seed 用三层结构：`[LOCK] IDEA / SURFACE` 齐全，`[FREE]` 明确放权，`[REGISTER]` 只 1 个样板拍
- [ ] seed 配额：占全文 ≤25%、微指令 ≤0.8/拍、不变量 ≤3 条
- [ ] 一致性：禁令与用法无互斥（禁光晕就别要求发光）；"镜头不停"与章卡定格已调和；无未定义量词 N
- [ ] seed 色板数量未突破 Signature 的配色约束（如「克制配色 2~3 色」）
- [ ] HOOK 在 0.5s 内且全片只有一个；hero 在 60–75%；结尾定格 0.8–1.2s；有 hex 色板与 Sound 行
- [ ] 品牌名虚构；未引用真实商标；素材许可约束在提示词中
- [ ] 全文不出现任何具体的 AI 助手/工具产品名

机械项（段落完整性、Signature features 逐字一致、帧数换算、时长档位、seed 密度、一致性 lint、色板冲突、产品名残留）运行校验脚本自动检查：

```bash
python3 scripts/check_prompt.py <生成的提示词文件> --template styles/templates/<编号>.md
```

脚本只覆盖机械项；论点是否立得住、样板拍够不够好，仍需人工判断。

### Step 5 · 交付

按以下字面结构输出（三部分，顺序固定）：

```
## 风格推荐
主推：<风格名> — <一句话理由>
备选：<风格名>（<一句话理由>）；<风格名>（<一句话理由>）

## 完整提示词
（单个代码块，可整体复制使用）

## 使用说明
（3–4 行：在空文件夹中交给能写代码并执行命令的助手；
环境要求——Node、Chrome、ffmpeg，3D 渲染系需 Blender；
提示词内已含确定性渲染与交付标准；成片后可用评审提示词迭代）
```

并主动告知：成片后可用 `references/review-rubric.md` 做"独立评审 → 按意见修改"迭代，至少两轮，评审维度为风格还原、创意、动效工艺、设计排版、质感收尾、声音同步、技术规格（1–10 分，目标 ≥9）。

## 执行提示词时的技术要点（供执行方参考，不必随提示词交付）

- 推荐管线：网页/脚本实现 `renderAt(t)`（任意时刻渲染一帧）→ 无头浏览器逐帧截图 → ffmpeg 与音轨合成 MP4；3D 用 Blender 脚本渲染 PNG 序列。
- 音频与画面共用一份节拍表（cue sheet）；响度 mastered 到 −14 LUFS integrated、true peak ≤ −1 dBTP。
- 渲染必须确定性：种子随机、物理/粒子预计算或闭式解、无实时时钟、无状态触发的 CSS 过渡。
